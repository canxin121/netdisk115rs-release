# v0.4.0：分层日志、原生批量改名与索引可靠性

本版集中发布前后端可靠性修复、Rust 分层日志，以及对照 115 APK 完成的批量协议和索引／缓存改进。继续只维护项目自己的本地媒体库，不恢复已移除的 115 原生观看、听单或相册管理。

## 文件操作与索引

- 受管整理计划使用 115 原生 `files_new_name[id]` 精确映射批量改名；不同目标名称不再逐文件调用 `files/update`。每次最多 1150 项，超过上限有序分批；失败不退化为单项请求风暴。
- 批量移动按每个文件的返回状态确认。任务中心与 File Provider 保留成功子集，失败或缺失结果不伪装成全部成功；直接移动 API 在失败信封中仍保留 `batch_results`。
- 源／目标按目录复核身份、名称及已知内容信息；拒绝重名、交换环和移动中间名称冲突，确认远端实际结果后才更新本地索引。
- 完整索引保留扫描开始前的变更窗口，避免漏掉扫描期间的修改。全量／增量提交校验队列代次、分页游标、父目录、重复项与快照；不完整空页不能触发错误收尾，迟到任务不能覆盖新扫描。
- 新增分页校验使用对象唯一键与 scope 成员主键，不从整代索引逐项扫描。详情并发读取合并，失效后的旧请求不能回写；目录移动清理两层后代路径缓存。
- 批量取链只接受本次请求的有效结果；畸形、重复或未请求记录不会污染缓存，坏行不拖垮有效兄弟项。

## Rust 日志

新增基于 tracing 生态的业务域／严重等级分层日志，支持文本或 JSON 终端输出、独立普通／告警 JSONL 文件、按时间轮转、保留数量和有界异步队列。请求、账号及后台任务携带关联字段，敏感信息在统一格式化层保护。

新增 `--log-filter`、`--log-format` 和管理员日志健康接口；诊断走 stderr，CLI JSON 结果继续走 stdout。配置重启与正常退出改为协作式停止并尝试刷新日志。

旧配置继续可用，文件日志默认关闭；需要落盘时显式配置 `server.logging.file.enabled: true`。日志目录相对配置文件解析；Unix 下已有目录需要私有权限。轮转限制时间／数量，不是磁盘字节配额；有损队列、强制终止或断电仍可能丢记录，不是不可丢失的审计账本。

## 权限、编辑与播放

- 用户安全属性修改失败不再改变实际权限；成功变更会撤销相关会话及媒体票据。任务 WebSocket 持续复核授权，不继续向失效会话推送。
- 文本／DOCX 保存与异步序列化固定原文件、账号和版本，防止切文件后旧操作覆盖新文档。在线覆盖保存需要有效 `expected_sha1`；依赖旧无版本写入方式的自建客户端需要调整。
- 媒体来源、票据和迟到请求按身份隔离；续播位置、清晰度重试及字幕读取不再串文件或串用户。
- CLI 成功和失败路径都保持 JSON 结果与日志分离，不追加破坏 JSONL 的重复纯文本错误。

## 升级与验证

本版不迁移数据库 schema，不清空现有索引、媒体库或云盘数据；建议升级前备份配置和数据目录，再使用已有安装器升级。重启后新二进制及 Web 资源一起生效。Android 草稿不包含在本版中。

发布候选在本地通过 **346 项 Rust 单元测试和 49 项集成测试，合计 395 项，0 失败**；其中本轮批量／索引审计新增 32 项。另有此前前端可靠性回归 237 项通过，后续未改变对应前端源码；TypeScript、94 个 Vue 模板与 Clippy 检查通过，Clippy 仍有非阻断提示。重型复杂度测试及真实云盘变更套件保持跳过，不宣称已经在用户文件上执行破坏性联调。

请求计数用例验证：2301 个不同名称拆为 1150／1150／1 三次改名 POST（不包含目录读取），32 个相同详情并发合并为一次读取。上游不提供跨请求原子快照；外部客户端竞争仍可能存在，遇到不能确认的结果会保留恢复状态。
